# platform-scorecard

> **Status: concept — RFC stage. There is no scoring code here yet, and no scores have been
> published.** Help us define the standard before anything gets scored.

An open standard for evaluating platform safety policies — scored against the public
documents platforms already publish. **No more self-grading.**

## How it would work

1. A platform's public safety policy is parsed against the scorecard schema.
2. Scores are generated across five dimensions.
3. Results are published openly, and a platform can dispute a score by pull request — in
   public, against the same criteria as everyone else.

## The five dimensions

| Dimension | 0–20 | Asks |
|---|---|---|
| Transparency | | Are the policies written in language a parent can read? |
| Enforcement | | Are consequences defined, and are they applied? |
| Reporting | | Can a user report harm easily, and hear back? |
| Age assurance | | Are the age gates meaningful, or decorative? |
| Data minimisation | | Is children's data minimised, or merely disclosed? |

## The obvious objection, stated by us rather than by a critic

**We are a platform. We intend to be scored by this.** A scorecard written by an interested
party is worth exactly as much as its criteria are public and its scores are disputable,
which is why both are, and why the standard is licensed for anyone to fork and run without
us.

If the first published scorecard has us at the top, do not believe it. Score us last and
score us in public.

## What would help

Proposing a dimension, challenging a criterion, or arguing that the whole exercise measures
policy rather than practice — which is the strongest objection to it and the one we do not
have a complete answer to.
